================================================================================
TELA: AUTENTICAÇÃO (Login + Troca de Senha)
================================================================================

-------------------------------------------------------------------------------
1. LOGIN
-------------------------------------------------------------------------------

URL: /login
Método: GET (carregar página) + POST (autenticar)

-------------------------------------------------------------------------------
1.1 API: POST /api/auth/login
-------------------------------------------------------------------------------

Descrição: Autentica o usuário e retorna token JWT

HEADERS:
  Content-Type: application/json

REQUEST BODY:
{
  "email": "string (email válido)",
  "password": "string (mínimo 6 caracteres)"
}

RESPONSE (200 - Sucesso):
{
  "success": true,
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "id": "cm5x123...",
    "email": "admin@botcrypto.com",
    "name": "Administrador"
  }
}

RESPONSE (401 - Não autorizado):
{
  "success": false,
  "error": "Email ou senha inválidos"
}

TABELAS ENVOLVIDAS:
- User (leitura)

CAMPOS NA TABELA User:
- email (para buscar usuário)
- passwordHash (para validar senha com bcrypt)
- id, name (para retornar ao frontend)

FLUXO:
1. Buscar usuário por email no banco
2. Comparar senha informada com passwordHash (bcrypt.compare)
3. Gerar token JWT com payload { userId, email }
4. Atualizar campo lastLogin com data/hora atual
5. Retornar token e dados do usuário

-------------------------------------------------------------------------------
1.2 API: GET /api/auth/me
-------------------------------------------------------------------------------

Descrição: Retorna dados do usuário logado (valida token)

HEADERS:
  Authorization: Bearer {token}

RESPONSE (200 - Sucesso):
{
  "success": true,
  "user": {
    "id": "cm5x123...",
    "email": "admin@botcrypto.com",
    "name": "Administrador"
  }
}

RESPONSE (401 - Token inválido):
{
  "success": false,
  "error": "Token inválido ou expirado"
}

TABELAS ENVOLVIDAS:
- User (leitura)

FLUXO:
1. Validar token JWT recebido
2. Buscar usuário pelo ID do token
3. Retornar dados do usuário

-------------------------------------------------------------------------------
1.3 API: POST /api/auth/logout
-------------------------------------------------------------------------------

Descrição: Realiza logout (frontend apenas remove token)

HEADERS:
  Authorization: Bearer {token}

RESPONSE (200 - Sucesso):
{
  "success": true
}

OBSERVAÇÃO: Backend é stateless, apenas valida token. Frontend remove o token do localStorage.

-------------------------------------------------------------------------------
2. TROCA DE SENHA (Tela Perfil)
-------------------------------------------------------------------------------

URL: /perfil (seção Segurança)

-------------------------------------------------------------------------------
2.1 API: PUT /api/auth/change-password
-------------------------------------------------------------------------------

Descrição: Altera a senha do usuário logado

HEADERS:
  Authorization: Bearer {token}
  Content-Type: application/json

REQUEST BODY:
{
  "currentPassword": "string (senha atual)",
  "newPassword": "string (mínimo 8 caracteres)",
  "confirmPassword": "string (deve ser igual a newPassword)"
}

RESPONSE (200 - Sucesso):
{
  "success": true,
  "message": "Senha alterada com sucesso"
}

RESPONSE (400 - Validação):
{
  "success": false,
  "error": "Nova senha deve ter no mínimo 8 caracteres"
}

RESPONSE (401 - Senha atual incorreta):
{
  "success": false,
  "error": "Senha atual incorreta"
}

TABELAS ENVOLVIDAS:
- User (atualização)

CAMPOS ATUALIZADOS:
- passwordHash (novo hash gerado com bcrypt)

FLUXO:
1. Validar token JWT
2. Buscar usuário pelo ID
3. Validar currentPassword com bcrypt.compare
4. Validar newPassword (mínimo 8 caracteres)
5. Validar newPassword === confirmPassword
6. Gerar novo hash com bcrypt.hash (salt 10)
7. Atualizar passwordHash no banco
8. Retornar sucesso

-------------------------------------------------------------------------------
3. MODELO DE DADOS - User
-------------------------------------------------------------------------------

TABELA: User

CAMPO               | TIPO        | OBRIGATÓRIO | DESCRIÇÃO
--------------------|-------------|-------------|----------------------------------
id                  | String      | Sim         | UUID (cuid) - Chave primária
email               | String      | Sim         | Email único para login
passwordHash        | String      | Sim         | Hash da senha (bcrypt)
name                | String      | Sim         | Nome do usuário
preferences         | JSON        | Não         | Preferências (tema, notificações)
lastLogin           | DateTime    | Não         | Último login
createdAt           | DateTime    | Sim         | Data de criação
updatedAt           | DateTime    | Sim         | Data da última atualização

EXEMPLO DE REGISTRO:
{
  "id": "cm5x1234567890",
  "email": "admin@botcrypto.com",
  "passwordHash": "$2a$10$N9qo8uLOickgx2ZMRZoMy.Mr/.cYqF7N",
  "name": "Administrador",
  "preferences": "{\"notificationsEnabled\":true,\"theme\":\"dark\"}",
  "lastLogin": "2024-01-15T10:30:00Z",
  "createdAt": "2024-01-01T00:00:00Z",
  "updatedAt": "2024-01-15T10:30:00Z"
}

-------------------------------------------------------------------------------
4. SEQUÊNCIA DE CHAMADAS (Frontend)
-------------------------------------------------------------------------------

1. Ao carregar o app:
   - Verificar se existe token no localStorage
   - Se existir, chamar GET /api/auth/me para validar
   - Se válido, manter usuário logado
   - Se inválido, redirecionar para /login

2. Ao fazer login:
   - Chamar POST /api/auth/login com email/senha
   - Salvar token no localStorage
   - Redirecionar para /dashboard

3. Ao fazer logout:
   - Remover token do localStorage
   - Redirecionar para /login

4. Ao trocar senha:
   - Chamar PUT /api/auth/change-password
   - Exibir toast de sucesso/erro
