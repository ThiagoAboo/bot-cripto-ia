1. VISÃO GERAL
===============================================================================

O backend do Bot Crypto IA é responsável por:

- Gerenciar múltiplos bots especializados por estratégia
- Persistir todas as configurações do sistema
- Processar ordens de compra/venda (manuais e automáticas)
- Gerenciar treinamento de modelos de IA por estratégia
- Armazenar logs e traces para auditoria completa
- Fornecer WebSocket para atualizações em tempo real

CONCEITO FUNDAMENTAL:

| Característica | Descrição |
|----------------|-----------|
| Bot por Estratégia | Cada bot implementa uma estratégia de análise diferente |
| Análise Multi-Moeda | Cada bot analisa dinamicamente qualquer moeda disponível |
| Decisão Autônoma | O bot decide qual moeda negociar no momento |
| Recomendação com Confiança | Cada ação tem um nível de confiança (0-100%) |


2. STACK TECNOLÓGICA
===============================================================================

| Camada | Tecnologia | Versão |
|--------|------------|--------|
| Runtime | Node.js | 20+ |
| Framework | Express | 4.18+ |
| Linguagem | TypeScript | 5.0+ |
| Banco de Dados | PostgreSQL | - |
| ORM | Prisma | 5.0+ |
| Autenticação | JWT + bcrypt | - |
| Validação | Zod | - |
| WebSocket | Socket.IO | 4.6+ |
| Logging | Winston | - |
| Orquestração assíncrona atual | Workers internos com polling + serviços Socket.IO | - |

OBSERVAÇÃO IMPORTANTE SOBRE A STACK REAL:
- A implementação atual NÃO usa Bull/Redis como fila principal
- O backend sobe workers internos a partir do `app.ts`
- O fluxo assíncrono atual combina:
  - polling workers para bots, treinamento e descoberta de pares
  - Socket.IO para atualização em tempo real do frontend
- Redis pode ser introduzido futuramente como evolução de infraestrutura, mas não faz parte da base operacional atual

4. MODELOS DE DADOS (PRISMA SCHEMA)
===============================================================================

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

// ==============================
// USUÁRIO
// ==============================
model User {
  id           String   @id @default(cuid())
  email        String   @unique
  passwordHash String
  name         String
  preferences  String   @default("{}")
  lastLogin    DateTime?
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt

  configurations  Configuration?
  transactions    Transaction[]
  balances        Balance[]
  logs            Log[]
  traces          Trace[]
  trainingSessions TrainingSession[]
}

// ==============================
// CONFIGURAÇÕES
// ==============================
model Configuration {
  id           String   @id @default(cuid())
  userId       String   @unique
  user         User     @relation(fields: [userId], references: [id])
  
  // Chaves API
  exchange     String   @default("binance")
  apiKey       String   @default("")
  secretKey    String   @default("")
  
  // Gerenciamento de Risco
  stopLossPercent      Float  @default(5.0)
  takeProfitPercent    Float  @default(10.0)
  leverage             Int    @default(1)
  maxTradeAmount       Float  @default(1000)
  maxTradeAmountUnit   String @default("USDT")
  
  // Moedas Permitidas
  allowedPairs         String @default("[]")
  
  // Taxas
  discountUsdtPercent  Float  @default(0.075)
  discountBnbPercent   Float  @default(0.075)
  minBnbBalance        Float  @default(0.01)
  
  // Opções Avançadas
  mode                 String @default("spot")
  orderType            String @default("market")
  slippagePercent      Float  @default(0.5)
  
  // Estratégias
  strategies           String @default("[]")
  
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}

// ==============================
// BOT (ESTRATÉGIA)
// ==============================
model Bot {
  id               String   @id @default(cuid())
  name             String
  strategyType     String
  description      String?
  status           String   @default("offline")
  isPaused         Boolean  @default(false)
  currentPair      String?
  lastAnalysis     DateTime?
  recommendedAction String?
  confidence       Float?
  modelVersion     String   @default("v1.0.0")
  modelUrl         String?
  parameters       String   @default("{}")
  
  createdAt        DateTime @default(now())
  updatedAt        DateTime @updatedAt

  transactions     Transaction[]
  trainingSessions TrainingSession[]
  traces           Trace[]
}

// ==============================
// TRANSAÇÃO
// ==============================
model Transaction {
  id         String   @id @default(cuid())
  date       DateTime @default(now())
  pair       String
  origin     String
  botId      String?
  bot        Bot?     @relation(fields: [botId], references: [id])
  type       String
  quantity   Float
  price      Float
  total      Float
  fee        Float
  status     String
  profitBrl  Float?
  profitPercent Float?
  
  userId     String
  user       User     @relation(fields: [userId], references: [id])
  
  createdAt  DateTime @default(now())
}

// ==============================
// SALDO
// ==============================
model Balance {
  id         String   @id @default(cuid())
  currency   String
  available  Float
  reserved   Float
  total      Float
  updatedAt  DateTime @updatedAt
  
  userId     String
  user       User     @relation(fields: [userId], references: [id])
  
  @@unique([userId, currency])
}

// ==============================
// HISTÓRICO DE SALDO
// ==============================
model BalanceHistory {
  id         String   @id @default(cuid())
  userId     String
  user       User     @relation(fields: [userId], references: [id])
  timestamp  DateTime @default(now())
  totalBrl   Float
  
  @@index([userId, timestamp])
}

// ==============================
// SESSÃO DE TREINAMENTO
// ==============================
model TrainingSession {
  id           String   @id @default(cuid())
  botId        String
  bot          Bot      @relation(fields: [botId], references: [id])
  status       String   @default("pending")
  startTime    DateTime @default(now())
  endTime      DateTime?
  
  config       String   @default("{}")
  metrics      String   @default("[]")
  bestEpoch    Int?
  bestValLoss  Float?
  modelUrl     String?
  
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
}

// ==============================
// LOG
// ==============================
model Log {
  id         String   @id @default(cuid())
  timestamp  DateTime @default(now())
  level      String
  module     String
  message    String
  details    String?
  
  userId     String
  user       User     @relation(fields: [userId], references: [id])
  
  @@index([timestamp])
  @@index([userId])
}

// ==============================
// TRACE
// ==============================
model Trace {
  id                String   @id @default(cuid())
  timestamp         DateTime @default(now())
  level             String
  module            String
  traceId           String
  parentTraceId     String?
  functionName      String
  message           String
  durationMs        Float
  botId             String?
  bot               Bot?     @relation(fields: [botId], references: [id])
  currentPair       String?
  recommendedAction String?
  confidence        Float?
  errorFlag         Boolean  @default(false)
  
  userId            String
  user              User     @relation(fields: [userId], references: [id])
  
  @@index([traceId])
  @@index([timestamp])
  @@index([userId])
}

7. REGRAS DE NEGÓCIO PRINCIPAIS
===============================================================================

7.1 DASHBOARD - Cálculos
-------------------------------------------------------------------------------

totalBrl = SUM(available * taxa_conversao_para_brl)

dailyProfitBrl = SUM(profitBrl) WHERE date >= now() - 1 day AND status = 'executed'

hitRate = (trades_com_lucro / total_trades) * 100

7.2 TRANSAÇÕES - FIFO para Cálculo de Lucro
-------------------------------------------------------------------------------

1. Buscar compras da moeda ordenadas por data (mais antigas primeiro)
2. Para cada compra, alocar quantidade vendida
3. profit = (preco_venda - preco_compra) * quantidade_alocada
4. Atualizar quantidade restante das compras

7.3 TREINAMENTO - Early Stopping
-------------------------------------------------------------------------------

Se early_stopping.enabled = true:
  - Monitorar loss de validação
  - Se não melhorar por N épocas (patience)
  - Interromper treinamento

7.4 LOGS E TRACES - Propagação de Trace ID
-------------------------------------------------------------------------------

1. Início da execução: gerar traceId único
2. Cada chamada subsequente: propagar mesmo traceId
3. parentTraceId = traceId da função chamadora
4. Permite visualização hierárquica no frontend

10.1.1 HEALTHCHECKS OPERACIONAIS
-------------------------------------------------------------------------------

Endpoints disponíveis:
- `GET /health/live`
  Retorna liveness do processo Node.js
- `GET /health/ready`
  Retorna readiness operacional com:
  - banco de dados
  - bot worker
  - training worker
  - runner de pair discovery
  - Binance user stream
- `GET /health`
  Alias para o readiness check

Uso recomendado:
- balanceadores e orquestradores devem usar `/health/ready`
- probes simples de processo podem usar `/health/live`
