-------------------------------------------------------------------------------
RN-CFG-001: Carregamento de Configurações
-------------------------------------------------------------------------------

API: GET /api/configurations

REGRAS:

1. Buscar configurações do usuário logado
   - Uma única linha por usuário (relação 1:1)

2. Se não existir configuração para o usuário:
   - Criar configuração com valores padrão

3. Valores padrão (defaults):
   - exchange: "binance"
   - apiKey: ""
   - secretKey: ""
   - stopLossPercent: 5.0
   - takeProfitPercent: 10.0
   - leverage: 1
   - maxTradeAmount: 1000
   - maxTradeAmountUnit: "USDT"
   - allowedPairs: "[]"
   - discountUsdtPercent: 0.075
   - discountBnbPercent: 0.075
   - minBnbBalance: 0.01
   - mode: "spot"
   - orderType: "market"
   - slippagePercent: 0.5
   - strategies: (JSON com estratégias padrão)

4. Estratégias padrão:
   [
     { id: "strategy_scalper", name: "Scalper V2", strategyType: "scalper", isActive: true, parameters: {...} },
      { id: "strategy_momentum", name: "Momentum Trader", strategyType: "momentum", isActive: true, parameters: {...} },
      { id: "strategy_trend", name: "Trend Follower", strategyType: "trend_follower", isActive: true, parameters: {...} },
      { id: "strategy_reversion", name: "Mean Reversion", strategyType: "mean_reversion", isActive: true, parameters: {...} },
      { id: "strategy_arbitrage", name: "Arbitrage Hunter", strategyType: "arbitrage", isActive: false, parameters: {...} }
   ]

5. A configuração de fees deve ser interpretada assim:
   - useBnbForFees = verdadeiro quando o usuário optar por usar desconto em BNB
   - minBnbBalance = saldo mínimo reservado para pagar taxas
   - reserveBnbForFeesEnabled = impede uso desse saldo mínimo em trades comuns

-------------------------------------------------------------------------------
RN-CFG-002: Validação de Parâmetros
-------------------------------------------------------------------------------

API: PUT /api/configurations

REGRAS DE VALIDAÇÃO:

| Campo | Regra | Erro |
|-------|-------|------|
| stopLossPercent | 0 < valor <= 50 | "Stop-loss deve ser entre 0 e 50%" |
| takeProfitPercent | 0 < valor <= 100 | "Take-profit deve ser entre 0 e 100%" |
| leverage | valor deve ser exatamente 1 | "Alavancagem deve permanecer em 1x no runtime spot atual" |
| maxTradeAmount | > 0 | "Valor máximo deve ser positivo" |
| discountUsdtPercent | 0 <= valor <= 1 | "Desconto USDT deve ser entre 0 e 1%" |
| discountBnbPercent | 0 <= valor <= 1 | "Desconto BNB deve ser entre 0 e 1%" |
| minBnbBalance | >= 0 | "Saldo mínimo BNB não pode ser negativo" |
| slippagePercent | 0 <= valor <= 5 | "Slippage deve ser entre 0 e 5%" |
| allowedPairs | Array de strings válidas | "Pares inválidos" |
| useBnbForFees | Boolean | "Uso de BNB para taxas inválido" |
| reserveBnbForFeesEnabled | Boolean | "Reserva mínima de BNB inválida" |
| pairDiscovery.autoDiscoveryEnabled | Boolean | "Configuração de descoberta automática inválida" |
| pairDiscovery.autoAddToAllowedPairs | Boolean | "Configuração de auto inclusão inválida" |
| pairDiscovery.autoRemoveFromAllowedPairs | Boolean | "Configuração de auto remoção inválida" |
| pairDiscovery.minSocialScore | 0 <= valor <= 100 | "Score social deve ser entre 0 e 100" |
| pairDiscovery.minMentions | valor >= 0 | "Mínimo de menções inválido" |
| pairDiscovery.maxPairs | valor > 0 | "Máximo de pares inválido" |
| strategies | JSON válido com estrutura correta | "Estratégias inválidas" |

REGRAS ADICIONAIS:
- exchange deve permanecer em "binance" até existir integração operacional homologada para outras corretoras
- mode deve permanecer em "spot" até existir suporte real para outro mercado
- Se reserveBnbForFeesEnabled = true, então minBnbBalance deve ser maior que zero
- BNB pode estar em allowedPairs, mas a reserva mínima deve continuar protegida
- excludedAssets nunca pode ser auto-incluído pelo pairDiscovery

-------------------------------------------------------------------------------
RN-CFG-003: Teste de Conexão com Exchange
-------------------------------------------------------------------------------

API: POST /api/configurations/test-connection

REGRAS:

1. Validar credenciais com a exchange selecionada

2. Para Binance:
   - Endpoint: GET /api/v3/account
   - Headers: { 'X-MBX-APIKEY': apiKey }
   - Assinar requisição com secretKey

3. Critério de sucesso:
   - Resposta 200 da exchange
   - Retornou dados da conta

4. Critério de falha:
   - Timeout (30 segundos)
   - Resposta 401/403 (chave inválida)
   - Resposta 4xx/5xx (erro na exchange)

5. Armazenar chaves apenas se salvar configuração (não no teste)

RN-CFG-004: Carregamento de Pares Disponíveis
-------------------------------------------------------------------------------

API: GET /api/exchange/pairs

REGRAS:

1. Buscar pares disponíveis na exchange (ex: Binance)

2. Filtrar apenas pares com quoteAsset = 'USDT'

3. Cache por 5 minutos para evitar chamadas excessivas

4. Ordenar alfabeticamente

5. Formato de retorno: ["BTC/USDT", "ETH/USDT", ...]

-------------------------------------------------------------------------------
RN-CFG-005: Reserva de BNB para Taxas
-------------------------------------------------------------------------------

Objetivo:
- Garantir que o usuário mantenha saldo mínimo de BNB para desconto de taxas na Binance

REGRAS:
1. Se useBnbForFees = false:
   - Nenhuma reserva especial de BNB é aplicada

2. Se useBnbForFees = true:
   - O sistema deve tentar pagar a taxa em BNB
   - minBnbBalance representa o saldo mínimo que deve permanecer livre

3. Se reserveBnbForFeesEnabled = true:
   - Trades com BNB só podem consumir o excedente acima de minBnbBalance
   - Caso o trade reduza o saldo abaixo do mínimo, a ordem deve ser bloqueada ou redimensionada

4. Se o saldo de BNB ficar abaixo de minBnbBalance:
   - Registrar alerta operacional
   - Permitir fallback para taxa sem desconto apenas se a política operacional permitir

-------------------------------------------------------------------------------
RN-CFG-006: Descoberta Automática de Moedas
-------------------------------------------------------------------------------

Objetivo:
- Automatizar inclusão e exclusão de pares em allowedPairs a partir de sinais sociais e/ou notícias

REGRAS:
1. O processo só roda se pairDiscovery.autoDiscoveryEnabled = true

2. Fontes elegíveis:
   - Reddit
   - RSS/News
   - X/Twitter
   - Telegram

3. Inclusão automática:
   - A moeda deve atingir minSocialScore
   - A moeda deve atingir minMentions
   - O ativo não pode estar em excludedAssets
   - O total final deve respeitar maxPairs

4. Remoção automática:
   - Só ocorre se autoRemoveFromAllowedPairs = true
   - Nunca remove pares protegidos/manualmente fixados
   - Nunca remove BNB se estiver configurado como ativo reservado para taxas

5. Se reviewRequired = true:
   - O sistema gera sugestão
   - A alteração só entra em vigor após confirmação
